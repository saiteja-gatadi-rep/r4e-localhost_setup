# Actions in NOVA reporting

Stories: ACT-5460 (Actions data source), ACT-5461 (P0 reports), ACT-5469 (report library). Epic ACT-5278.

## 1. What is this
Actions (tickets) is now the fifth data source in NOVA Dashboards & Reports, turned on per tenant with one feature flag.

```mermaid
flowchart LR
  U["Tenant user"] --> N["NOVA Dashboards and Reports"]
  N --> R["Reviews"]
  N --> S["Surveys"]
  N --> L["Listings"]
  N --> P["Rep Score"]
  N --> A["Actions (NEW)"]
  style A fill:#d9f2d9,stroke:#2e7d32,stroke-width:2px
```

## 2. Why NOVA
One self-serve engine, builder and library for every source, instead of a separate fixed set of ticket reports.

```mermaid
flowchart LR
  subgraph Legacy["Actions reports today"]
    L1["Fixed set of reports"] --> L2["Tickets read from Mongo"]
  end
  subgraph Nova["Actions in NOVA"]
    N1["Self-serve dashboards and widgets"] --> N2["Shared report engine"]
    N2 --> N3["Ticket data in Elasticsearch"]
  end
  Legacy -. "same numbers" .-> Nova
```

## 5. How it works
The report engine offers Actions only when the switches are on; the report library lists Actions dashboards only for flagged tenants.

```mermaid
%%{init: {"flowchart": {"wrappingWidth": 420}}}%%
flowchart TD
  UI["NOVA UI"] --> API["Report engine (r4e-api-internal)"]
  API --> FF{"Switches on?"}
  FF -- "no" --> HIDE["Actions is not offered"]
  FF -- "yes" --> SRC["Actions source: 16 metrics, 23 attributes, 9 filters"]
  SRC --> ES[("Ticket index in Elasticsearch")]
  UI --> LIB["Report library (r4e-report-two)"]
  LIB --> ALLOW{"Tenant has the Actions flag?"}
  ALLOW -- "yes" --> LIST["Actions dashboards listed, Source Type: Actions"]
  ALLOW -- "no" --> HIDDEN["Not listed"]
```

## 6. Where the ticket data comes from
Tickets flow into the Elasticsearch index through the pipeline; NOVA only reads the index. On QA the pipeline is not live yet, so the index has a few hand-loaded test tickets.

```mermaid

  style NOVA fill:#d9f2d9,stroke:#2e7d32,stroke-width:2px
```
